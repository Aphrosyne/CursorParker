# CursorParker

CursorParker 是一个轻量、免安装的 Windows 光标停放工具。它在检测到键盘输入、且鼠标自最近一次移动后保持静止达到设定时间时，将鼠标指针暂时移到当前显示器边缘，减少指针遮挡文字或其他内容的情况；再次移动鼠标时，程序尝试恢复停放前的位置。

程序以后台进程运行，不创建常驻窗口，不替换系统光标，也不安装键盘钩子或使用 UI Automation。配置保存在程序目录中，开机启动通过当前用户的“启动”文件夹快捷方式管理。

## 软件组成

| 文件 | 用途 |
| --- | --- |
| `cursor_parker.ps1` | 停放器主体：读取配置、检测输入和保护条件、停放并恢复光标。 |
| `launcher.ps1` | 中文控制台设置入口：显示运行状态，启动或停止停放器，并管理开机启动快捷方式。 |
| `光标停放器设置.cmd` | 打开中文设置菜单。 |
| `光标停放器开关.cmd` | 静默切换停放器的启动或停止状态。 |
| `CursorParker.ini` | 保存闲置时间和游戏排除路径。 |

## 运行流程

1. 停放器启动后读取 `CursorParker.ini`，取得闲置时间和游戏排除路径。
2. 后台逻辑每 50 毫秒检查鼠标位置、支持的输入按键、前台窗口和系统光标限制状态。鼠标位置变化或保护状态结束时会重新开始闲置计时；检测到输入按键后，如果鼠标静止时间已达到设定值，程序就会尝试停放光标。因此，输入发生时静止时间已经达到阈值的情况下，停放可能随输入立即发生。
3. 停放前记录原位置，并将指针移到它当前所在显示器的右侧、靠近右下方的位置。
4. 用户移动鼠标后，程序尝试将指针恢复到原位置。若恢复时按住鼠标键，程序会等按键释放，避免拖动过程中发生光标跳转。

无标题栏且覆盖显示器的全屏窗口、系统光标被程序限制在局部区域，以及配置的排除程序处于前台时，会暂停停放逻辑。如果已停放的光标遇到这些保护条件，程序会先尝试恢复位置。配置了排除路径但无法读取前台进程路径时，程序按受保护程序处理。

## 配置

编辑程序目录里的 `CursorParker.ini`：

```ini
[General]
IdleSeconds=1

[ExcludedGames]
Game1=C:\Games\Example\game.exe
; Game2=D:\Games\AnotherGame\game.exe
```

- `IdleSeconds` 是鼠标自最近一次移动后保持静止的时间阈值，输入按键用于触发停放资格；若输入发生时静止时间已达到阈值，停放可能立即发生。数值可以使用小数，例如 `1.5`；有效范围为 `0.05` 到 `3600` 秒。无效条目会被忽略；如果没有有效值，则使用启动参数值，默认是 `1` 秒。
- 在 `[ExcludedGames]` 下，每个 `GameN` 填一条游戏 EXE 的完整绝对路径。路径必须和实际运行的 EXE 完全对应，不支持通配符；非绝对路径或扩展名不是 `.exe` 的项目会被忽略。
- 不确定游戏 EXE 路径时，可在任务管理器“详细信息”页右键游戏进程，选择“打开文件所在的位置”。
- 配置只在下次启动时读取。保存后重新启动 CursorParker 即可生效；配置文件存在但无法读取时，停放器不会启动。
- INI 支持 UTF-8、UTF-8 BOM 和 UTF-16 BOM。无 BOM 文件会先按严格 UTF-8 解码，失败时才回退到当前 Windows ANSI 编码。为避免中文路径被误判，建议使用 UTF-8 BOM 或 UTF-16 BOM。

## 启动与开机启动

项目保留两个入口：

- `光标停放器设置.cmd`：打开中文命令行菜单，显示“运行中”“正在停止”或“未运行”状态，提供运行开关，以及“启用开机启动”“禁用开机启动”两条明确操作。
- `光标停放器开关.cmd`：静默切换停放器进程的启动或停止，不显示提示或等待窗口。通过资源管理器双击 CMD 文件时，控制台可能短暂闪过。

运行开关通过停止或启动后台进程控制运行状态，不提供暂停或恢复模式。停止后进程退出；再次启动时重新读取配置。如果停放器仍在等待光标恢复时重复切换，操作会保持为停止请求，不会排队重启；进程停止后再切换即可启动。

开机启动通过当前用户“启动”目录中的 `CursorParker.lnk` 实现，不修改注册表，也不需要管理员权限。启用会创建或更新本项目的快捷方式；禁用只删除可识别为本项目的快捷方式。如果同名快捷方式无法通过目标、指向 `cursor_parker.ps1` 的 `-File` 参数和说明标记确认归属，程序会提示手动检查并保留该快捷方式。程序和配置仍保留在本目录。

快捷方式的完整路径通常是：

```text
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\CursorParker.lnk
```

`%APPDATA%` 指当前 Windows 用户的漫游应用数据目录。如果“启动”目录被系统重定向，实际位置以 Windows 返回的用户 Startup 目录为准。

## 技术实现与运行环境

- 面向 Windows 10 和 Windows 11，使用系统自带的 Windows PowerShell 5.1；不需要管理员权限、第三方运行环境或额外依赖。
- 停放器主体使用 PowerShell 编排逻辑，并通过 `Add-Type` 在运行时加载调用 Windows 原生 API 的 C# 代码，用于查询和设置光标位置、前台窗口、显示器范围、输入状态及系统光标限制。
- 输入检测使用 Windows 异步按键状态轮询，不安装键盘钩子。停放器使用命名互斥体限制重复实例，并通过停止事件接收退出请求；设置入口另用互斥体协调重复控制操作。
- 两个 CMD 入口文件只含 ASCII 字符；中文控制台脚本 `launcher.ps1` 使用 UTF-16LE BOM 编码，以适配 Windows PowerShell 5.1 和中文路径。

## 已知限制

- 停放期间首次移动鼠标时会先恢复停放前的位置，因此可能看到一次轻微的位置跳动。
- 停放期间按住鼠标键移动时，程序会等所有鼠标键松开后再恢复原位置；点击和实际拖动仍发生在停放点。
- 停止进程时，如果鼠标键仍按住或系统暂时不允许移动光标，程序会等待恢复条件满足后再退出。强制结束进程可能导致停放前的位置无法恢复。
- 如果程序通过 `ClipCursor` 限制的区域不包含停放前的位置，停放器会等限制解除后再恢复；如果显示器布局变化导致原坐标不再可用，系统调整后的可用位置会作为恢复位置。
- 按键检测使用异步状态轮询，快速输入可能偶尔漏检；程序不能确认应用中的实际输入框焦点。
- 未列入排除列表的程序中，单独按字母、数字或标点也可能触发停放。
- 全屏保护根据窗口是否覆盖显示器及窗口样式判断，无法覆盖所有窗口化游戏；可将游戏 EXE 完整路径加入排除列表。
